# OBTC 多学科评审清单（基于 2025-10 至今实现）

> 用途：本文件从《OBTC 技术实现全景说明》里拆分出的评审内容，供跨学科团队单独审阅。  
> 范围：区块链/密码学、网络工程、经济机制、法律合规、运维安全、社会治理。  
> 说明：技术机制细节请参阅《OBTC_技术实现全景_2025-10至今.md》。

---

## 1. 评审目标

本评审不讨论“愿景正确性”，而重点核对三件事：

1. **规则可执行**：核心规则是否具备明确激活条件、通过条件、失败条件。  
2. **跨层闭环**：Consensus、Mining、Wallet 是否形成端到端一致行为。  
3. **风险可治理**：异常场景下是否有可预测的安全降级与运维处置空间。

---

## 2. 建议评审顺序

1. 先读技术全景文档的 **Section 1-2**（架构与参数），统一术语和边界。  
2. 再读 **Section 3-7**（Expiry / REAP / Replay Protection），评估规则强度。  
3. 然后读 **Section 8-9**（Wallet 能力与场景矩阵），评估用户侧可操作性。  
4. 最后读 **Section 10-12**（可观测性、白皮书结构化建议、Glossary），评估可运营性与可解释性。

---

## 3. 多学科评审清单

## 3.1 区块链与密码学（Blockchain / Cryptography）

- Replay protection 是否在 Legacy / SegWit / Taproot 路径等价强制？
- Activation gating 是否会引入历史交易兼容断层？
- Marker digest 的绑定粒度是否足够防重排、防错配？
- Canonical order 与 max-inputs 是否充分抑制实现分歧与资源攻击面？

## 3.2 网络工程（Network Engineering）

- 新命名空间（network magic / port / HRP / HD version / coin type）是否覆盖全链路？
- 节点引导与网络隔离策略是否具备生产可用性？
- REAP 不入 mempool 后，是否有补偿监控保障可见性？

## 3.3 经济机制（Economics）

- 30% Tax 是否能长期激励矿工持续处理 expired UTXO？
- 模板预留 REAP weight 是否对普通交易市场造成显著挤压？
- Dust fold 是否可能引发用户“名义返还但体感损失”的认知冲突？

## 3.4 法律合规（Legal / Compliance）

- “过期后仅系统路径可处理”在目标法域是否触发资产处置争议？
- 用户是否被充分告知到期机制、续期路径与后果？
- 协议层、钱包层、用户操作层责任边界是否明确且文本化？

## 3.5 运维与安全（Ops / Security）

- 是否有统一指标面板覆盖 Expiry/REAP/Renew 三条链路？
- 是否定义 auto-renew failure backoff 与 budget 相关告警阈值？
- CI 中 flaky 网络测试是否与核心功能正确性测试分层评估？

## 3.6 社会治理（Social Governance）

- 到期规则的复杂度是否会放大普通用户认知负担？
- 是否出现“信息不对称导致的结构性损失”风险？
- 社区教育材料能否用可验证事实解释“为何到期、如何避免损失”？

---

## 4. 评审输出建议模板

建议每个学科评审结论统一输出为：

1. **结论级别**：通过 / 有条件通过 / 不通过  
2. **关键证据**：支持结论的观测或验证点  
3. **风险等级**：High / Medium / Low  
4. **整改建议**：可执行、可验证、可追踪的改进项  
5. **复核条件**：达到哪些条件后可关闭该风险项

---

## 5. 评审摘要（可用于会议纪要）

OBTC 当前实现的评审关注重心应放在：

- 规则是否具备可执行性与可预期失败语义；
- 三层系统是否在复杂场景下保持行为一致；
- 运行期是否具备足够可观测性，支撑风险前置处置；
- 对外说明是否足够清晰，避免用户因认知缺口承担非预期损失。

如上述四点均有证据支撑，则可判定系统已具备“从研发走向可运营”的基础条件。
